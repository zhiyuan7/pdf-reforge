# PDF 回炉所 · PDF Reforge

**旧 PDF 进炉，结构清楚的新书稿出炉。**

PDF 回炉所用 MinerU 的识别结果恢复书籍结构，通过 DeepSeek 做少量、简短的判断，再生成带目录、特殊块样式和内部跳转的 PDF。适用于有原始目录的中文数学教材及类似书籍。

仓库只保留当前生成流程的程序、配置与排版资源。原始书籍、识别结果、模型缓存、处理报告和生成的 PDF 均留在本地，不提交到 GitHub。

## 当前流程

```mermaid
flowchart LR
    A[原始 PDF 与 MinerU 结果] --> B[目录标题匹配]
    B --> C[正文清理与特殊块抽取]
    C --> D[本地编号引用映射]
    D --> E[LaTeX 排版与 PDF 检查]
```

| 阶段 | 处理内容 | 模型使用 |
| --- | --- | --- |
| 1. 标题匹配 | 读取原书目录图片，匹配标题、层级与位置，最后判定习题标题 | DeepSeek 读取目录和判定习题标题 |
| 2. 正文整理 | 删除边栏、清理段首标点、跨页配对、本地匹配关键词并识别特殊块 | 只返回判断或块号 |
| 3. 引用映射 | 搜索正文中的类型＋编号，登记候选并生成可确定的跳转 | 本地规则，无模型调用 |
| 4. PDF 生成 | 直接读取保存的前三阶段结果，生成书稿、目录、书签与链接 | 本地排版，无模型调用 |

### 第二步的规则

1. 第一步匹配到的标题优先成为标题，即使 MinerU 原先将其识别为页眉或页脚。
2. 按 MinerU 类型删除 `header`、`footer`、`page_number`。图注、表注和脚注继续保留。
   `page_footnote` 在 DeepSeek 正文处理前单独归类，按开头原标号匹配圆圈数字、普通数字、上标及星号等符号，只查同一原物理页。仅在注释标号和正文引用点均唯一时建立对应；没有标号、没有引用点或有歧义时保存未匹配原因，不猜测关系。记录保存在 `footnotes.json`。脚注退出正文关键词判断和跨页配对，跨页正文可绕过脚注继续合并；原脚注文字和公式完整保留。
3. 只清理**每个文字块开头**不应出现的句号、逗号、后引号、后括号等；保留前引号、前括号，以及块内部的文字、公式和标点。
4. 将每页最后一个文字块与下一页第一个文字块配对，由 DeepSeek 返回 `{"m":1}`（合并）或 `{"m":0}`（不合并）。
5. 使用用户可编辑的候选集合，分为定理公式、例题、小标题三组。全篇本地扫描每个文字块的开头及每个换行符后的开头；允许段首缩进，正文中间的提及不计数。优先匹配更长、更具体的形式：例如“例题”优先于“例”，深层编号优先于浅层编号，合法罗马数字形式优先于重叠的单字母形式。罗马数字仅认单独的 i/v/x（含大写）及规范的同大小写多字符编号，例如 II、IV、vi；单独的 c/d/l/m（含大写）归字母，IC、IIII、iV 等不作为罗马数字。小写字母与大写字母分为独立类型，例如“a.”属于“小写字母.”，“A.”属于“大写字母.”。同一位置只计入一个候选，每个关键词或编号形式累计至少 10 处才进入后续判断；不再抽取六个标题范围，也不调用 DeepSeek 提取关键词。编号形式支持数字、汉字数字、小写字母、大写字母、罗马数字、希腊字母及括号、分层形式，最多六层，例如“数字.数字”“汉字、”“(汉字)”“大写字母.数字”；全角括号和点号归一为半角。旧“字母”候选自动展开为大小写两类，分层中的各字母层独立展开。候选集合、所有候选的计数及每处匹配位置保存到 `keyword_discovery.json` 和 `keyword_discovery/matches.json`。
6. 仅将通过次数阈值的匹配位置交给 DeepSeek。换行内的匹配按原文地址生成独立候选，前面的普通正文保留。定理等类型将候选块与随后两个块交给 DeepSeek，只返回 `{"y":0,"b":[]}` 或 `{"y":1,"b":[1,2]}`。编号小标题跳过完整编号中的点号，再寻找第一个句末标点（`。 . ． ！ ! ？ ?`），只发送从候选开头到该标点的原文（包含标点）；没有句末标点时发送整个候选块。公式内部的点号不作为句末标点。返回 `{"y":1}` 时按原文地址拆出这一段标题，其余文字保持普通正文；返回 0 的候选留待编号连续性复核。
7. 例题单独返回题目块 `q` 与解答块 `a`，例如 `{"y":1,"q":[1,2],"a":[3]}`；明确的同块“解”起点按原文地址分开保存。例题与其他特殊块的窗口都按 3、9、18、30……扩展，直到确定范围或到下一已确认声明/匹配标题。所有文字与公式保持原样。
8. 第一步结束时由 DeepSeek 标记哪些标题属于习题部分，保存到 `exercise_headings.json`。该范围及所有下属章节跳过所有编号形式的小标题识别和样式，编号与原文作为普通正文完整保留；进入范围外的下一章节后恢复正常识别。
9. DeepSeek 判断之后增加编号连续性复核。只有原本 DeepSeek 确认数超过 10、已经保留的编号形式才可作为补回起点；因数量不足被整类过滤的形式不会重新启用。同一匹配标题范围、同一上级和同一编号形式内，按原文顺序划分连续编号序列；至少有一个已确认标题的序列，将其中被 DeepSeek 判为 0 的候选补回为标题。可以向前、向后连续补回多项，例如只确认 `1.4.3` 时补回已有候选 `1.4.1、1.4.2`；只确认 `(1)` 时补回末尾 `(2)、(3)、(4)`。遇到缺号、重复、倒序或重新从 1 开始就划分新序列；不同章节、上级、大小写或编号形式分别处理。无确认标题的整串候选、习题范围、与其他特殊块重叠的候选、请求失败的候选不补回，也不凭空创建未匹配到的标题。补回标题沿用截句和拆块规则，不调用模型；原答复保持 0，连续性依据另存 `subheading_continuity.json` 及对应结果记录。
10. 连续性复核结束后，按每个关键词或小标题编号形式分别统计最终确认数（含连续性补回），只有 **超过 10 个** 才保留特殊块身份。“例题”与“例”、“数字.”、“小写字母.”与“大写字母.”分别统计；不超过 10 个的只丢弃特殊块标注，原文保留。最终计数与过滤记录保存到 `special_block_filter.json`。

旧版保存结果在打开特殊块列表、生成预览或生成整书时也按新规则重新分类大小写字母和罗马数字，并执行连续性复核及最终过滤，不调用 DeepSeek。先前仅因次数不足被丢弃的确认结果也参与重新分类；判否候选只有满足连续性规则才补回，范围冲突的结果不采用。列表及排版使用同一筛选规则；引用映射和样例缓存随变更更新，旧 PDF、识别文件和判断记录保留。手动删除的类型仍保留删除状态，“保存并重新识别”才清空删除设置。

定理等特殊块只包含**表述**，不包含证明、推导或后续讨论；证明继续留在普通正文中。例题保留题目及其解答，分别记录原文范围。编号小标题先由 DeepSeek 判断，再以已确认标题为依据补回连续编号的漏判候选。连续性规则也可能将同一编号序列中的普通列表项补回，需要核对这类边界情况。第二步不做 OCR 纠错。无法确定的判断会保留来源并记录问题。

排版时，若单条公式被 OCR 赋予多个冲突的 `\tag` 编号、编号括号残缺，或编号在文本模式下包含非法的上下标，则使用该条公式的原书图片，保留符号和编号，避免 LaTeX 编译中断。其余公式继续使用原生数学排版；原始 OCR 与已保存的处理数据不变，图片保留记录写入 `reports/coverage.json` 的 `tex_compatibility`。

若纯图页面的节点标签被 OCR 拆成了带残缺编号的公式，则从原 PDF 保留包含图和全部邻近标签的完整区域，图注继续单独排版，来源锚点仍指向该图。此处理要求页面只有一个图对象、没有正文或已编辑的标签；记录保存在 `source_order_layout`。

### 名称从哪里来

名称由本地程序从对象声明处的原文提取，不让模型重新起名。例如：

```text
定理4（数列收敛的柯西准则）……
→ 类型：定理；编号：4；名称：数列收敛的柯西准则
```

支持中英文括号、引号、书名号、尖括号、破折号等形式，以及嵌套符号和跨块名称。只有明示且能确定的名称才进入记录；没有明确名称时留空。记录保留名称原文和来源范围，框标题显示原有类型、编号与名称，正文开头不重复名称。

引用映射只使用类型和编号。名称、例题编号和没有明确编号的语义指代不参与匹配；多个候选时保留原引用并记录候选。

## 安装

当前流程在 **Python 3.12 / Linux** 上验证。需要 XeLaTeX、latexmk 和中文字体。

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

在 `.env` 中填写自己的 `DEEPSEEK_API_KEY`。在 `book_config.json` 中设置模型、接口地址、并发数和字体；目录读取使用图片输入，因此所配置的接口与模型需要支持图片及 JSON 输出。

DeepSeek 连接按接口协议使用 `HTTPS_PROXY` 或 `HTTP_PROXY`，没有对应代理时使用 `ALL_PROXY`，并遵守 `NO_PROXY`。支持 HTTP 与 SOCKS5 代理（`socks://` 按 `socks5://` 处理）；无关的代理配置不会阻止客户端启动。客户端配置错误会直接报告，只有收到的模型结果不符合要求时才报告判断无效。

已有完整 MinerU 结果时无需安装或运行 MinerU。需要重新识别时，额外安装：

```bash
pip install -r requirements-mineru.txt
```

Linux 用户可用以下脚本在项目的 `.tools/` 中安装排版工具；其他系统可自行安装 TeX Live 与 latexmk：

```bash
python install_book_tex.py
python main.py --check-local
```

默认正文字体为 `Noto Serif CJK SC`，标题字体为 `Noto Sans CJK SC`，需要在系统中安装。图注使用仓库附带的霞鹜文楷字体。`--check` 在本地检查基础上额外检查密钥是否存在，不发送模型请求。

## 本地网页界面

安装网页入口所需依赖并启动本地服务：

```bash
source .venv/bin/activate
pip install -r requirements-web.txt
python serve.py --port 8765
```

浏览器访问 <http://localhost:8765>。端口被占用时可通过 `--port` 改用其他端口。网页资源和图标保存在仓库内，前端无需 Node.js 或外部 CDN。

上传 PDF 后填写书名和作者，再开始处理。书籍信息直接使用表单输入，并与 YAML 入口共用校验；程序不另外识别或猜测书名和作者。文件上传显示传输进度；后台显示 MinerU、标题匹配、正文整理、引用映射和排版的真实阶段与计数。MinerU 显示当前识别的原 PDF 页码、已持久保存或复用的累计页数，以及单页内部版面分析和内容识别的计数；块数不会充当整书已识别页数。加载模型等没有计数的操作显示等待状态。

在“匹配规则”页签中，可按组添加、修改、删除候选项，每行一项；留空可以关闭整组。新书稿开始处理时保存这些设置；已有书稿可以点击“保存并重新识别”，复用已有 OCR、标题与有效判断缓存，在新目录生成识别结果，同时清空之前手动删除特殊块及其类型的记录；之前删除的小标题编号形式也会重新识别。只点击“保存候选集合”不会清空删除记录。重新识别失败时继续保留原识别版本和删除设置。候选集合按书稿保存，也可以恢复默认。命令行入口可在配置 JSON 中设置 `keyword_candidates`：

```json
{
  "keyword_candidates": {
    "statements": ["定理", "公式", "命题", "公理", "定义"],
    "examples": ["例题", "例", "Example"],
    "subheadings": ["数字.数字", "数字.", "汉字、", "(汉字)", "小写字母.", "大写字母."]
  }
}
```

`keyword_candidates` 为 `null` 时使用默认候选集合；显式提供时，三组列表构成完整候选集合，未列出的关键词不匹配。“习题”“练习”“问题”不参与特殊块关键词匹配，已有候选集合中的这三项也会过滤。自定义例题词沿用题干/解答判断；自定义定理公式词沿用表述范围判断。

MinerU、标题匹配和正文整理完成后，任务停在“排版样式”。正文字号先填入推荐值 10.5 pt，可设为 9–18 pt；小标题按实际发现的编号形式分别设置字号，包括数字、汉字、小写字母、大写字母、罗马数字和希腊字母。大小写字母各自计数、设置字号、生成样例及删除；旧“字母”字号自动应用到拆分后的两类，已有明确大小写字号优先。默认一／二／三层分别推荐为 15／13／12 pt，须大于正文且不超过 36 pt，固定蓝色加粗；同层不同编号形式各有独立设置和样例预览。其他类型可统一选择颜色。例题采用细上边线、粗下边线，题目用楷体、解答用细笔画仿宋（FandolFang），字号跟随正文。

点击“生成预览”显示一段真实正文对照，并从每种特殊块、每种小标题编号形式中选一个完整样例，使用正式排版样式渲染文字、公式和图片。所有样例保留相同的正文栏宽，字号对比不会因裁图而失真；多页样例保留全部页面。此过程不做引用映射或整书编译。字号和配色与预览一起独立保存，调整后可重新生成。旧版本书稿可点击“更新特殊块识别”，复用已有 OCR、标题和有效的模型判断缓存，补充习题标题判定，并在新目录保存第二步结果。

点击“生成整本 PDF”才完成本地引用映射和整书排版，复用识别和正文整理结果。整书 PDF 支持翻页、缩放、目录跳转、按类型查看特殊块、跳转到块所在的实际 PDF 页面，以及下载 PDF。独立公式仍使用原生数学排版。

已匹配脚注在正文引用处提交给页底脚注排版，保留原标号并采用较小字号与分隔线；未匹配脚注在原文位置提交独立脚注，不插入虚构的正文引用。渲染报告保留脚注来源和实际页面，可检查引用点与脚注是否位于同页。

在“排版样式”中点击某一类型的“删除此类型”，可取消这一类全部特殊块的身份与样式，原文、公式及后续正文保留。定理、例题等按显示的类型整体删除；小标题按具体编号形式分别删除，例如删除“数字.”不影响“数字.数字”或“罗马数字.”。重新生成样例预览或整书 PDF 后体现修改。删除类型无需调用 DeepSeek，设置随书稿保存，并在服务重启、生成预览和生成整书后继续应用；“保存并重新识别”及“更新特殊块识别”会清空这些设置。先前的识别结果和 PDF 版本保留。

书稿任务、输入文件和每次排版结果保存在 `output/web/`，服务重启后可继续访问。已有完整书稿会自动出现在“最近书稿”中，可以直接调整配色；重新排版保存为独立版本，已有结果保留。重启时未完成的任务会显示“处理已中断”，可继续处理。

## 准备书籍

将 PDF 放在本地输入目录，例如 `input_pdfs/book.pdf`。复制配置示例并填写书名和作者：

```bash
cp book_metadata.example.yaml input_pdfs/book.book.yaml
```

书名和作者读取 YAML，不自动猜测。`exclude_pages` 使用从 1 开始的原 PDF 物理页码；未知书籍不会默认删除封面或版权页。通常自动找到目录页，也可在 `book_config.json` 的 `toc_pages` 中指定物理页码。

完整 MinerU 结果目录需要包含 `manifest.json`、`middle_json.json` 与识别图片资源。当前适配 MinerU 4.0.10 的 `docvortex.middle` 2.0 格式；输入 PDF 的 SHA-256 必须与清单一致。

## 运行完整流程

复用已有 MinerU 结果，只运行标题匹配及后续步骤：

```bash
python main.py \
  --pdf input_pdfs/book.pdf \
  --mineru-dir output/book/mineru \
  --metadata input_pdfs/book.book.yaml \
  -o output/book/reforged
```

最终 PDF 位于 `output/book/reforged/pdf/latex/main.pdf`。如果不指定 `--mineru-dir`，程序会在输出目录中复用已有完整识别结果，或调用本地 MinerU 生成结果：

```bash
python main.py --pdf input_pdfs/book.pdf -o output/book
```

也可单独完成识别，再运行后续阶段：

```bash
python run_mineru.py input_pdfs/book.pdf -o output/book/mineru --pages all
```

MinerU 每完成一页就原子保存该页的文字、公式、图片数据和校验信息，默认缓存位于输出目录旁的 `.cache/mineru_inference/pages/`；网页任务使用书稿目录内的 `mineru_cache/pages/`。识别中断后，以相同参数重跑即可跳过校验通过的页面，只重做未完成或损坏的页。`--checkpoint-dir` 可指定缓存位置；`--refresh-inference` 强制重做。输入 PDF、模型参数或版本改变时不会混用旧页缓存。全部页面完成后再导出统一结果包，旧版完整缓存仍可复用。

MinerU 推理在本地运行；第二步的文字输入和目录页图片会提交给配置的 DeepSeek 接口。

## 分阶段运行

每个阶段使用独立的输出目录，后续阶段读取已保存结果：

```bash
# 第一步
python main.py --match-headings \
  --pdf input_pdfs/book.pdf --mineru-dir output/book/mineru \
  --metadata input_pdfs/book.book.yaml -o output/book/headings

# 第二步：完整处理所有标题范围
python main.py --process-sections \
  --pdf input_pdfs/book.pdf --mineru-dir output/book/mineru \
  --heading-report output/book/headings -o output/book/content

# 第三步
python main.py --map-references \
  --pdf input_pdfs/book.pdf --mineru-dir output/book/mineru \
  --heading-report output/book/headings \
  --processed-book-dir output/book/content -o output/book/references

# 第四步
python main.py --render-processed-book \
  --pdf input_pdfs/book.pdf --mineru-dir output/book/mineru \
  --metadata input_pdfs/book.book.yaml \
  --processed-book-dir output/book/content \
  --mapping-report output/book/references -o output/book/pdf
```

同一输入与提示会复用经过校验的响应缓存。可通过配置 `shared_cache_dirs` 复用其他本地缓存目录；命中的有效响应会保存到当前阶段缓存，使本次结果不再依赖旧目录。改变来源或标题结果时，请使用新的结果目录。

运行记录提供真实请求数、缓存命中数和 token 用量。配置中的费率只是费用估算参数，需要按实际服务更新；缓存重放不会产生新的模型费用。

## 项目结构

```text
main.py                    当前流程的唯一主入口
serve.py                   localhost 网页入口
run_mineru.py              可选的本地识别入口
mineru_checkpoint.py       MinerU 推理缓存与完整性检查
pipeline_progress.py       MinerU 进度事件
install_book_tex.py        本地排版工具安装
book_config.json           通用运行配置
book_metadata.example.yaml 书籍配置示例
book_pipeline/
  application/             四阶段编排与命令行
  ingestion/               原文、公式与精确来源范围
  ai/                      DeepSeek 请求、缓存和用量记录
  structure/               标题、正文块、名称和引用
  publishing/              LaTeX、编译、页面与导航检查
  web/                     本地 HTTP 接口、任务状态与前端界面

models/                    排版所需字体及许可证
```
